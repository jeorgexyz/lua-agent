# Example Output

Real transcripts, generated by running this repo. Nothing hand-written or
edited — same policy as [lua-llama's examples](https://github.com/jeorgexyz/lua-llama/tree/main/examples).

Regenerate everything here with:

```bash
lua54 record.lua
```

Put side by side these are the capability boundary: a 42M TinyStories model
answers immediately and never picks a tool; a 1.5B instruct model picks the
right tool and chains two of them, but still cannot recover from a dead end
or decline to confabulate.

## Loop transcripts

Each one has a `traces/<id>.jsonl` beside it, and each transcript's header
carries the exact command that replays it:

```bash
lua54 main.lua "<task>" --replay traces/<id>.jsonl --tools <tools>
```

| File | Shows |
|---|---|
| `calc-single.txt` | the simplest complete loop, start to answer |
| `read-then-calc.txt` | multi-hop: one tool's output feeds the next |
| `recover-parse-error.txt` | truncated JSON → parser message → corrected |
| `recover-missing-file.txt` | bad path → specific error → corrected |
| `loop-bait.txt` | the loop detector firing on a repeated call |
| `oversized-observation.txt` | eviction under a 400-token budget |
| `denied-write.txt` | the approval gate refusing a write |

These are what makes the transcripts evidence rather than illustration: the
`replay` group in `test.lua` replays every trace and re-runs its eval check,
so **if a transcript here stops reproducing, a test fails.**

## A caveat, stated plainly

The loop transcripts use a **scripted model** — a fixed list of turns per
task, defined in `eval/tasks/tasks.lua`. They are recordings of the loop's
behaviour, not of a model's.

That is deliberate, and it is the same reason `eval/run.lua --ablate` uses
scripted turns: an ablation of the loop needs the model held constant. If the
model were real, you could not tell whether removing the loop detector changed
the outcome or whether the model simply sampled differently that run.

The scripts are not strawmen — each encodes a mistake real models actually
make (a truncated call, a wrong path, a re-read that never helps, an oversized
read). But no claim is made here about any model's ability to *choose* well.
That claim lives in `constrained-vs-free.txt`, which is real inference, and
its answer for a 15M model is: it cannot.
